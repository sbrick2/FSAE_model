# FSAE 赛事回放

仿真中心顶部的“赛事回放”页签直接显示完整回放界面。在“时域闭环 → 历史结果”加载结果或完成仿真后，进入回放页即可播放；也可在回放页点击“选择时域结果文件”，同步加载到主 GUI。分析绘图页原有“赛事回放”按钮会切换到同一页签。

切换加载的结果会同步刷新回放，重新从结果起点暂停；离开回放模块会暂停播放，返回时保留时刻。关闭主窗口释放回放定时器，并取消和清理尚未完成的视频导出。导出期间切换结果会提示先完成或取消导出。

独立启动方式仍可用：在项目根目录运行 `launchFSAERaceReplay` 选择规范化的圈速结果 MAT 文件。

```matlab
app = launchFSAERaceReplay();
% 也支持已加载的 result 结构或指定文件：
app = launchFSAERaceReplay(resultFile);
```

不重新运行仿真。7DOF、10DOF、reference-speed 与 adaptive 驾驶员结果使用同一界面。

## 布局与操作

左右列宽约为 60% : 40%。左侧为车辆、赛道和四轮力主画面，四个角落分别显示 GG 图、数据表、小地图和踏板请求。左上角的实时 GG 图以 Ay 为横轴、Ax 为纵轴，单位均为 g，显示回放时刻之前的加速度轨迹和当帧插值点；跳转到更早时刻会同步回退轨迹。GG 图使用本次结果的固定等比例刻度，缺失加速度不补造当前点。右上角数据表将名称、数值、单位分列对齐，包含经过计时、本圈计时、车速、总机械功率、电池功率、Ay/Ax、转向请求和赛事进度。赛道地图嵌入主画面左下角，驾驶员请求开度嵌入右下角；窗口缩放时同步调整角落位置和坐标范围，保持赛道比例和全景完整。导出使用相同布局规则。

右侧“轮胎利用率与电机状态”按 FL/FR/RL/RR 排列，每个摩擦图旁边有对应电机的三根竖向柱：转速 rpm、实际转矩 N·m、机械功率 kW。三个量使用独立量程；每种量的四轮量程相同，在本次回放中保持固定。每柱显示实际数值和单位。转矩、功率的零线位于中部，负值向下。主画面右下角的加速、制动驾驶员请求使用竖向条形图，量程固定为 0–100%。

播放/暂停、归零、前后逐样本、0.25–4 倍速和时间滑块均使用统一时钟。视角支持跟车北向、跟车车头朝上和全景；“视野”调整跟车范围，“轮旁值”和“数据表”控制叠层显示。建议窗口不小于 1366×768。

```matlab
app.seek(10);                       % 跳转至仿真时间 10 s，暂停
app.step(1);                        % 下一个原始样本
app.setView("heading");             % 车头朝上
app.setPlaybackSpeed(2);
app.play();
app.pausePlayback();
close(app.UIFigure);                % 释放窗口及其定时器
```

## 数据含义

- 每轮有独立的蓝色 Fx 与橙色 Fy 箭头，共八个分量；方向同时考虑车轮转向、车身航向和视角旋转。箭头共用固定力尺度。单位为 kN，零值长度为零，缺失值隐藏并显示“不可用”。
- 摩擦图横轴 Fy、纵轴 Fx，均显示实际力值，单位 kN，不作容量归一化。灰色参考边界的横、纵半轴分别为当帧横向与纵向容量，容量不同时呈椭圆；有限路面绝对摩擦上限另用橙色虚线圆显示。四轮在同一帧共用相同刻度，量程包含实际力和可见边界。MF62 参考边界并非严格可达力包络；框内仍分别标注重算参考利用率和原始记录利用率。保存的利用率可能已裁剪到 100%。
- 原始踏板请求存在时直接显示。当前驾驶员结果通常只有加速度指令，使用当次驾驶员最大加减速度转换为“等效请求开度”。它与实际加速度、执行器输出和真实踏板传感器开度不同。缺少指令或对应满量程时显示“不可用”。
- 同一帧的机械功率由实际转矩 × 电机角速度计算，缺少基础量时使用已记录功率。任一电机功率缺失，总机械功率也显示“不可用”。电池功率是独立的电气通道。
- 连续信号插值，驾驶员请求、圈序号和路面输入保持前值；不跨越缺失姿态补造运动。本圈起点不能可靠确定时，本圈计时显示“不可用”。

## 新结果与历史结果

新的 `runLapSimulation` 在运行开始前捕获有效赛道、车辆几何、驾驶员和轮胎参数，保存在 `result.Meta.Replay`。结果保存器保留此快照，也支持显式 `ReplaySnapshot=`，不使用当前车辆字典补造历史快照。

赛道自动加载的优先级为：显式 `Track` / `TrackFile`、运行快照中的赛道、结果记录的赛道文件或 `Config.Track.DataFolder`、项目 `trackdata/<记录的赛事名称>.mat`。记录目录迁移后可在当前项目中匹配对应赛事；采用记录的 `Config.Track.Name` 或 `Meta.Event`，与 GUI 当前的仿真赛事选择无关。自动加载只读取现有文件，不重新生成或覆盖赛道。底部状态栏显示实际来源；“自动加载赛道文件”表示使用赛道文件，区别于历史运行快照。

历史结果缺少参数快照时仍可回放实际轨迹、已记录力和仪表；车辆尺寸标为示意，容量边界不可用。无法匹配赛道文件时显示实际轨迹，并保留“加载赛道”入口。只有能核对来源时才手工指定当次运行参数，或覆盖自动选择的赛道：

```matlab
app = launchFSAERaceReplay(resultFile, TrackFile=trackFile);
app = launchFSAERaceReplay(resultFile, Snapshot=snapshot);
% 1366×768 / 1920×1080 的初始窗口：
app = launchFSAERaceReplay(resultFile, WindowSize=[1920,1080]);
% 也可在已有 UI 容器中复用完整回放：
replay = launchFSAERaceReplay(resultFile, Parent=panelHandle, ProjectRoot=projectRoot);
```

界面中的“加载赛道”接受含 `track` 或 `Track` 的 MAT；“加载参数快照”接受含 `snapshot` 或 `result.Meta.Replay` 的 MAT。轮胎模型支持 `simple`、`mf62`、`ttc_map`。MF62 优先使用当次 `TireMFParameters` 29 维向量。时变路面可在 `result.Environment.RoadGripScale/RoadMuLimit` 或显式快照中保存与 Time 对齐的 Nx4 序列，不用常量替代。

## MP4 导出

点击“导出 MP4”设置时间范围、帧率和分辨率，采用当前倍速与视角。导出暂停播放并锁定操作；取消或关闭窗口会清理本次未完成文件。成功后恢复原回放时刻及播放状态。

```matlab
report = app.exportVideo("E:\FSAE_model\results\race_replay.mp4", ...
    TimeRange=[10,15], FrameRate=30, Resolution=[1920,1080], Speed=1);
% 查看导出墙钟耗时及采样、绘图、截图、缩放、编码的分项耗时：
report.ElapsedSeconds
report.Timing
```

默认不覆盖已有文件；显式 `Overwrite=true` 或 GUI 保存对话框确认覆盖后，仍先写临时文件，成功才替换目标。取消或编码失败保留原文件。输出帧尺寸统一为所选偶数宽高，独立于 Windows 显示缩放；固定帧率视频时长量化误差不超过一帧，末帧采用选择范围的终点。

默认使用普通 figure/axes 绘制完整仪表盘，与界面共用帧采样和绘图对象构造逻辑，避开嵌套 UI 网格的逐帧截图开销。仍保留 `Renderer="ui"` 参数，可通过 `app.exportVideo(..., Renderer="ui")` 使用原 UI 捕获方式。导出的左列（主画面与小地图）和右列维持 60% : 40% 的宽度比例；图形窗口的内部画布最小为 1280×720，更小的输出会缩放到选定尺寸。

验证环境为 MATLAB R2026b、Windows MPEG-4 VideoWriter；UI 捕获方式要求 MATLAB R2025a 或更新版本及系统可用编码器。

本机 1366×768 / 1920×1080 的完整刷新实测约 8.4 / 9.6 fps，尚未达到原定 20–30 fps 目标。播放按实际经过时间推进并丢弃显示帧；离线导出保持所选固定帧率。

导出帧率是成品视频的播放帧率。导出逐帧采样、更新完整仪表盘、捕获图形窗口，再以质量 95 编码为 MPEG-4；若截图尺寸与所选输出尺寸不同，还会逐帧缩放到目标分辨率。帧捕获会自行刷新图形，导出循环不再重复调用 `drawnow`。播放可以跳过来不及显示的帧，导出需要处理全部输出帧。例如 120 s、30 fps、1× 倍速需要 3600 帧，不能以播放流畅度估算导出速度。缩短时间范围或降低帧率可直接减少帧数；1280×720 可减少捕获与编码的像素量。

2026-09-29 本机对同一份测试数据、1080p、30 fps、12 帧短样例进行预热后测量：原导出约 10.51 s，图形导出约 4.08 s，整体约快 2.57 倍。新导出中采样、绘图、截图与编码分别约 0.042、0.214、1.260、0.212 s；窗口准备约 2.15 s。这是短样例的实测，不是整圈导出耗时预测。720p 同一短样例约 3.30 s。原始记录见 `results/replay_export_optimization/baseline.json` 与 `final.json`；另验证了 640×360 输出及保存了当次轮胎快照的真实运行结果。

## 验证

运行 `tests/RaceReplayDataTest.m`、`tests/FSAERaceReplayAppTest.m`，以及受影响的 `tests/FSAESimulationAppTest.m`。数据测试覆盖采样、角度、Fx/Fy 方向、缺失数据、请求口径、功率和模型容量；界面测试覆盖十二根电机柱、播放、视角、跳转、导出尺寸与帧数、实际画面变化、两种渲染器数据一致性、取消、失败及关闭清理。本次导出优化的 17 项回放测试全部通过。

四角布局修订通过九项相关回归测试，覆盖 GG 单位、插值、回退与缺失数据、1366×768/1920×1080 下的叠层位置及赛道比例、GUI/图形导出一致性、两种渲染器的 MP4 和主 GUI 加载/关闭。真实保存结果的界面截图、短视频和验证记录见 `results/replay_live_gg/`。
